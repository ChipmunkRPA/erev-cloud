# Spec questions: phase 01 FND (Foundation: repository, toolchain, gates and kernel base)

Archived from `PROGRESS.md` verbatim when GATE-FND was ticked. SPEC-Q-4 (setup step 9) and SPEC-Q-7 (`get_clock(request)`) were closed by FND-6 and FND-10 and removed from `PROGRESS.md` before this archive; their ids are not reused.

- SPEC-Q-1 (DG-MK-typecheck vs TypeScript 5.9): `tsc -b frontend --noEmit` fails TS6310 because the referenced `tsconfig.node.json` must be composite and emit. Used `tsc -b frontend`; `tsconfig.json` sets `noEmit`, the node project emits declarations only into `frontend/node_modules/.tmp/`.
- SPEC-Q-2 (DG-ENV-05 vs FND-1 scope): DG-MK-setup has nine steps, so `scripts/setup.sh` was added although FND-1 lists no setup script. Recipes that are one tool invocation per line stay in the Makefile.
- SPEC-Q-3 (DG-RUN-20 vs DG-MK-build): the proxy guard throws only for the dev server and `vite preview`; `vite build` and Vitest load the same config without a target.
- SPEC-Q-5 (DG-MK-lint literals): ruff and eslint run from the repo root with `--config backend/pyproject.toml` and `--config frontend/eslint.config.js`; prettier and eslint take `frontend/e2e` only once it exists (`$(wildcard)`).
- SPEC-Q-6 (DG-ENV-16, `--names`): required names are the six DB URLs, the three master keys and `EREV_DEMO_TOTP_SECRET`; `EREV_DEMO_PASSWORD` is not required, so setup never fails on it.
- SPEC-Q-8 (FND-2 scope vs DG-TST-15): `NetworkBlocked` and the patch installer live in `backend/tests/support/network.py`; conftest wires the session-scoped autouse `no_network` fixture. Only `127.0.0.1`, `::1` and `AF_UNIX` are allowed; `create_connection` is checked before DNS resolution.
- SPEC-Q-9 (DG-KRN-CFG-02 URL pair vs DG-ENV-10 hosted production): required except `EREV_ENV=production` with `EREV_KEY_PROVIDER=gcp`; the URL getters check the DG-ENV-13 allow-list; blank counts as unset.
- SPEC-Q-10 (DG-LOG-01 vs OPR-21 allow-list): allowed keys = OPR-20 fields, `method`, `exception`, `*_id(s)`, `*_code(s)`, `*_count`, `*_ms`, `count`, `register_logger_fields` extensions; DG-LOG-07/SAR-19 keys dropped; strings redacted (secrets, email) and truncated at 2,000 chars (`exception`: SPEC-Q-36).
- SPEC-Q-11 (DG-LOG-07 guard mechanics): the guard taps structlog events before any processor runs, plus standard-library records. Tests that log forbidden values deliberately install a fresh pipeline (`log_stream`). DG-TST-06 and DG-TST-07 enforcement belong with `controls.yaml` (REQ-CTL-001).
- SPEC-Q-12 (secrets-check scope `git ls-files`): `--cached --others --exclude-standard`, so new files are scanned before commit; a non-git `--root` walks with `.git/` and the DG-LAY-08 ignores.
- SPEC-Q-13 (DG-MK-secrets-check self-test mechanics): fixtures are named `<PATTERN_ID>.<ext>` and `clean.txt` holds near misses; they are covered by six allow-list entries rather than a scope exclusion. `PEM_BLOCK` matches a line whose left-stripped text starts `-----BEGIN `. An invalid or missing allow-list exits 1.
- SPEC-Q-14 (DG-KRN-KEY-04 blob layout vs §5.19 `wrap`/`unwrap` signatures): `wrap` returns `KEK id length ‖ KEK id ‖ nonce ‖ encrypted DEK ‖ tag`; `KeyRing.encrypt` emits `b"erev1" ‖ that ‖ nonce ‖ ciphertext+tag`; the canonical bytes of `context` are the associated data of both layers. `current_hmac_key_id` returns version 1 locally.
- SPEC-Q-15 (05 KEY-04 vs one fixed blob layout): the hosted `GcpKeyProvider` KMS-decrypts the KEK material (secret `app-kek`) once per process and wraps DEKs with AES-256-GCM like the local provider. Hosted HMAC keys are numbered versions of secrets `security-hmac` and `audit-hmac-<tenant id>` under prefix `EREV_GCP_SECRET_PREFIX` (default `erev-`).
- SPEC-Q-16 (05 CFG-13 vs dev-guide §2.3): optional `Settings` fields `EREV_GCP_PROJECT`, `EREV_GCP_KMS_KEK`, `EREV_GCP_SECRET_PREFIX`, absent from `.env.example`; `build_keyring` raises `SettingsError` naming them when `gcp` lacks them.
- SPEC-Q-17 (DG-ENV-08 `make licence-check` before FND-16): cryptography, cffi, pycparser, alembic, mako added; closed by FND-16 (passes).
- SPEC-Q-18 (BUILD_SPEC FND-5 `test_dg_tst_11` decimal `7310582651376169812` vs DG-TST-11 key `0x6572657654455354`): followed the dev-guide hex ("erevTEST" = 7310016704070112084).
- SPEC-Q-19 (FND-5 `test_krn_db_01` vs DG-KRN-DB-04): the following session is `identity_session(request_id=…)`; LIFO app pool; commit/rollback events clear the context marker; `platform_session` waits for `security_event`; `committed_db` yields `TestDatabase` until `tenant_factory` exists.
- SPEC-Q-20 (FND-6 `test_db_01_forbid_mutation` "inside a rolled-back owner transaction … UPDATE as erev_app"): `erev_owner` cannot `SET ROLE erev_app`, so the IM-A probe is committed as owner, the erev_app steps (UPDATE, DELETE, TRUNCATE → 42501) run on an identity session, the owner steps run in a rolled-back transaction, and the probe is dropped at teardown.
- SPEC-Q-21 (04 §18 step 0001 "schema `erev`" vs DG-MIG-01 `version_table_schema = "erev"`): `env.py` runs `CREATE SCHEMA IF NOT EXISTS erev` first; with no head left after a downgrade it drops `alembic_version` and then `DROP SCHEMA erev` without CASCADE. DB-14 (b) allow-lists `alembic_version`. Offline (`--sql`) mode raises.
- SPEC-Q-22 (DB-14 (g) IM class not in the catalogue): `apply_class` writes `COMMENT ON TABLE erev.<t> IS '<class>'` plus grants, DB-01 and IM-M DB-02 triggers; DB-03/DB-04 via `create_trigger`; tenant tables get `fk_<t>__tenant` (SC-V also approval and supersedes FKs); `global_reference=True` grants SELECT only.
- SPEC-Q-23 (FND-6 `test_dg_mk_db_reset_refuses_running_stack` "exits 1" vs GNU make exiting 2): the recipe exits 1, make exits 2; the test asserts both. The database check moved into `erev db reset`, so a refusal issues no SQL. `RUN_DIR` is a Makefile variable.
- SPEC-Q-24 (T-PLT-11 `description erev.label NOT NULL` vs no description text): descriptions in `CATALOGUE` are loop-written copy; codes, areas and flags are verbatim.
- SPEC-Q-25 (T-REF-08 "ISO 4217 currency table" vs no list): `ISO_4217` holds the 159 active List One codes with minor unit 0 to 4 (fund codes included); metals, XBA to XBD, XDR, XSU, XUA, XTS, XXX and withdrawn codes (ANG, CUC, HRK, SLL, ZWL, BGN) are omitted.
- SPEC-Q-26 (FND-7 `test_dg_arc_09_pg_enum_labels_equal_python` vs 04 §18 "enum types are created by the first revision whose tables use them"): revision 0002 creates no enum type, so the test compares every type present and proves the comparison on a rolled-back probe type.
