## 1. The question (candidate 109, unchanged)

S10-R-26 treats `AllocatedState.concession_history` as the dated source subledger of concession additions, and stage 08 (D-88 L7-5-Q-4 (iii)) and stage 06 (S06-R-09 under `CREDIT_OR_REFUND`) each write the addition under their own producing event. Stage 10's `_concessions` nevertheless builds ONE `CONCESSION` refund component per obligation from the aggregate quota and dates it by an inferred boundary (`_concession_event`: the settled `CONTRACT_AMENDED`, else the latest `MODIFICATION` segment's event, else the `TP_CHANGE` event). With a `MODIFICATION` segment on the obligation, the concession created by a later `ESTIMATE_CHANGED` is dated by the earlier modification, an earlier credit memo consumes it (S10-R-14 "oldest first" by `created_on`), and the refund liability the concession should create never appears (VC-CHK-113: November RL 60 / CL 0 expected, RL 0 / CL 60 produced; the December release absent). Whether the aggregate-origin sentence or the producers' dated intent governs is D-98 question 109.

## 2. Proposed amendment texts (draft wording for the governed decision)

**ENGINE_SPEC_B §10.2.4, `CONCESSION` component (new rule text, proposed id S10-R-14a "Dated concession origin").** A `CONCESSION` refund quota that its dated `concession_history` conserves (every addition posted ≥ 0 and Σ posted = quota.a_posted; `check_history` unchanged) yields one component per addition: created on the producing event's effective date, cited to that event (`contract_event` source, member `refund_component`, value = the addition's posted amount), keyed `<group>@<entity>/CONCESSION/<producing event key>/<obligation subject key>`, carrying the producer's `revenue_basis`, and ordered by the producing event's ENG-06 position. A zero-posted addition (deferred targeted cent) creates no component. Selecting a boundary (`_concession_event`) is the fallback for a quota without conserving dated history only; it is not a substitute for the dated origin.

**S10-R-14 (consumption; amended sentence).** A credit memo reduces billing (S10-R-03) and, in the same ENG-06 position, consumes open `TERMINATION`, then `CONCESSION`, then `UNCLAIMED_PROPERTY` components in dated-origin order — a component's origin is its creating event's ENG-06 position (effective date, record_seq, event key) — and consumes only components whose origin precedes the memo in that order: a component created after the memo, or on the memo's day but recorded after it, is never consumed by it. `RETURN` and `VARIABLE_CONSIDERATION` components are never consumed. [J unchanged.]

**S10-R-26 (`aggregate_node` sentence; amended — revised after Codex 1510).** `aggregate_node` names the obligation's one `concession_created_cum` node at t: with one dated component it is that component's node (`rl.concession.v1`, mode `open`, input its producing event); with several it is the obligation-level node valued at the Σ of those components' own `concession_created_cum` nodes, computed by `rl.concession_total.v1` (mode `sum`) whose inputs are exactly the component node ids — each component node (subject = component key, `rl.concession.v1`) cites its own producing event, so the aggregate preserves every component's lineage and never cites one event at the total. The element never cites the aggregate node as an input (count-once numerator unchanged); the dated portions and their `concession_portion@<event>` nodes are unchanged.

**Table 14-A / stage 14 (JET-05c, JET-04b; clarifying sentence).** JET-05c stays one part per obligation and period end: the Σ of the obligation's dated `CONCESSION` components created by then, citing every component's node. JET-04b stays per component (cause = component key), netting each component's created amount (D-88 L7-5-Q-4 (2)); with dated components a concession created in period p first appears in p, not at the inferred boundary.

**§16.3 node table (draft rows).** `concession_created_cum` | obligation (the aggregate) and, with several dated components, `<group@entity>/CONCESSION/<event>/<obligation>` (each component) | period | `rl.concession.v1` (mode `open`; one component: the obligation node is the component's node) and `rl.concession_total.v1` (mode `sum`; the obligation aggregate over the component nodes; params `as_of`, `components`). **Formula registry (draft).** `rl.concession_total.v1` joins `erev_engine.formulas.FORMULAS` and stage 10's `FORMULA_IDS` (kernel tests `test_stage_registry` / `test_formula_ownership` / `test_trace` enforce both), and the BUILD_SPEC / `docs/build-spec/12-engine.md` stage-10 formula list is to be updated together with this wording. `refund_liability` and `refund_liability_consumed@<memo>` unchanged (per component).
