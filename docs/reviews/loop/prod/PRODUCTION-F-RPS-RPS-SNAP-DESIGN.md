## 0. Summary of decisions

- **D1 — Contract (as agreed with F-CLO, record §8; F-CLO-prep :99–:130).** `backend/erev_api/domain/reports/snapshots.py` exposes `SnapshotScope` (frozen, keyword-only dataclass: `entity_id: UUID`, `book_code: str`, `period_id: UUID`, `known_at: datetime`), `DatasetBuilder = Callable[[UnitOfWork, SnapshotScope], Encoded]` and `SNAPSHOT_DATASETS: Mapping[str, DatasetBuilder]` keyed by the E-64 literal. `Encoded` is the engine's dataclass (`kind`, `content` — the S15-R-18 UTF-8 CSV, `file_sha256`, `row_count`, `control_totals`) produced by the pure `encode(Dataset, control_totals)`; the kind set is the engine constant `SNAPSHOT_KINDS` (twelve, E-64 order). F-CLO's `freeze_datasets` calls `SNAPSHOT_DATASETS[kind](uow, scope)` per kind, stores the bytes and writes T-CLS-05 — unchanged.
- **D2 — TEN adapters now, one per registered builder; each wraps the REAL report builder through the framework's own resolution and rendering contract** (§2, §3): the frozen dataset of a kind is the report's rows as the report would compute them for the lock's entity, book and period at `known_at` — never a parallel query, never a re-rounding.
- **D3 — The two register kinds are a NAMED DEPENDENCY, not adapters.** `MODIFICATION_REGISTER` (producer: F-CTR / CTR-17 modification provenance) and `MANUAL_ADJUSTMENT_REGISTER` (producer: F-CLO manual adjustments) have no builder module and no `BUILDERS` entry. They are ABSENT from `SNAPSHOT_DATASETS` and named in `SNAPSHOT_DEPENDENCIES` (kind → owner, producer, the §15.2.7 row key and control totals they must supply); `dataset_for(kind)` refuses them by name (`SnapshotDependencyMissing`). F-CLO's existing check (`freeze_datasets`: kinds missing from the registry → `ProducerMissing` naming them, before any write, "no partial manifest") therefore keeps refusing the lock BY NAME until both producers land. No empty dataset, no stub, no substitute (Codex 1505 §3). Consequence stated plainly: the public `tests/domain/close/test_lock.py::test_lock_writes_certification_and_snapshots` (twelve rows) stays blocked on the two producers (and on CLO-10's JE_COMPLETE), not on this registry.
- **D4 — Scope → report parameters through `framework._resolve` with the catalogue's `parameters_schema`** (§3): the adapter builds the report request a user would make for the lock's scope (`entity_codes` = the entity's code, `book`, the period selector the report declares — `period_key`, or `from_period_key` = `to_period_key`; `known_at` = the scope's instant as text) and resolves it exactly as `create_run` does (defaults, `PARAMETER_DEFAULTS`, the `historical` basis because `known_at` is supplied — READ-1: the builders keep the supplied cutoff, which is S15-R-18's "runs each report with `known_at = cutoff_known_at`"). Any resolution finding refuses by name (`SnapshotRefusal`, a `RuntimeError` like `ProducerMissing`: the lock fails, nothing saved). No `period_lock_id`, no filters, no view / dimension / band choice (S15-R-19: the frozen dataset carries no such choice).
- **D5 — Encoding = the engine's S15-R-18 `encode` over the report's canonical cell texts** (§4): columns `row_key` (text) then every report column in report order; each cell the DS-FMT-25 canonical text of the report's CSV renderer (money → the API-S-Money `amount` with exactly the currency's minor-unit places — the report already quantized it; currency columns are ordinary report columns in all ten kinds; booleans `true` / `false`; dates ISO; timestamps RFC 3339 `Z`; None → empty); `control_totals` = the builder's own control totals verbatim (the §15.2.7 per-kind totals with their per-currency entries, as 04 rows 1.40 / 1.44 / 1.58 define them). A duplicate `row_key` or a row lacking a column refuses by name (the engine's `Dataset` guards) — S15-R-20a "exactly one row per key". This is byte-identical in form to the encoding `tests/domain/reports/test_as_locked.py::_frozen_from` already freezes and to what `locked.report_data` reads back (text-kind columns). **Q1 for Codex:** text-kind money cells (report-governed text) versus the engine `money` kind (`Money(minor, currency, minor_unit)` → the same text through `format_money`) — the texts are equal by construction; the text kind admits empty cells, the `money` kind would refuse them. Default: text.
- **D6 — No source binding is recorded for a frozen dataset** (`sources=None`): T-CLS-05 carries no binding; the frozen bytes ARE the artefact (S15-INV-06); an as-locked run reads them and never rebuilds. The disclosure pack's later needs (a binding beside the frozen file) are a separate ruling, not assumed.
- **D7 — Read side unchanged.** `locked.locked_dataset(uow, report_code, lock_id)` / `locked.report_data` (F-RPS, CLO-8) are the read side F-CLO-prep :110 names as `read_snapshot`; this note adds nothing there. `framework.create_run` keeps requiring `BUILDERS` membership (`:999–:1028`); the two registers' as-locked runs stay unreachable until their builders exist — CLO-8b's selector surface alone cannot reach them (Codex 1505 §3).
- **D8 — Sequence preserved.** CLO-8b-after-frps3 → CLO-8c-after-frps4; CLO-8c drives reports with the lock `test_lock.py:465–513` returns; existing private fixtures (`test_as_locked.py`'s hand-written lock with one CONTRACT_BALANCES snapshot) are repointed only when the public chain can produce a lock — not in this slice.

## 1. The contract, verbatim

```python
# erev_api/domain/reports/snapshots.py (to be written)
@dataclass(frozen=True, slots=True, kw_only=True)
class SnapshotScope:
    entity_id: UUID
    book_code: str
    period_id: UUID
    known_at: datetime            # the lock's cutoff instant (tz-aware)

type DatasetBuilder = Callable[[UnitOfWork, SnapshotScope], Encoded]

SNAPSHOT_DATASETS: Mapping[str, DatasetBuilder]        # TEN entries (D2); E-64 literals
SNAPSHOT_DEPENDENCIES: Mapping[str, SnapshotDependency]  # TWO entries (D3): owner, producer, row key, totals

class SnapshotRefusal(RuntimeError): ...              # a named refusal of one kind's freeze (nothing saved)
class SnapshotDependencyMissing(SnapshotRefusal): ...  # the two register kinds until their producers land

def dataset_for(kind: str) -> DatasetBuilder           # SNAPSHOT_DATASETS[kind] or the named dependency refusal
```

Invariants pinned by CPU tests: `set(SNAPSHOT_DATASETS) | set(SNAPSHOT_DEPENDENCIES) == set(SNAPSHOT_KINDS)` and the two sets are disjoint; every adapter's report code is `locked.SNAPSHOT_KIND_BY_REPORT`'s inverse for its kind and a member of `framework.BUILDERS`; the two dependency kinds are exactly the codes `locked.SNAPSHOT_KIND_BY_REPORT` maps that are NOT in `BUILDERS`.

## 3. Scope → parameters (D4)

`given = {"entity_codes": [<code of scope.entity_id>], "book": scope.book_code, <period selector>: <period_key of scope.period_id>, "known_at": utc_text(scope.known_at)}` — `known_at` supplied ⇒ `resolve_basis` yields the `historical` basis (READ-1), matching S15-R-18. Everything else the schema declares takes its default through the SAME code path as an API request, so the frozen dataset equals the report a user would see for that scope (S15-R-19: "its CSV output is the frozen bytes themselves" for the as-locked run of that report). `period_lock_id` is never given (a freeze is the live evaluation that produces the lock's dataset). Findings → `SnapshotRefusal` naming the report, the field, the rule and the message (never a partial dataset). The entity code is read live at the freeze (the freeze IS the live evaluation; 3c-1's retained-configuration rule concerns bound reruns, not freezes).

## 4. Encoding (D5)

`Dataset(kind, columns=(Column("row_key","text"), *(Column(c.key, "text") for c in data.columns)), rows=...)` with each row `{"row_key": row["row_key"], **{c.key: csv.cell(c, "value", row.get(c.key))}}` — `csv.cell` is the report CSV renderer's DS-FMT-25 text (`outputs/csv.py:31`): money → `value["amount"]` (exact minor-unit places; the currency is its own column in all ten kinds: `currency`, or `txn_currency` / `functional_currency` for `JE_POPULATION`), integer / decimal / date / timestamp / boolean / codes / actor / text per that function, None → `""`. Then `engine.encode(dataset, data.control_totals)` — rows sorted by row key, canonical CSV, SHA-256 (S15-R-18). `Encoded.control_totals` carries the builder's totals verbatim (`Mapping[str, Any]` at runtime — the engine's annotation says `Mapping[str, str]`; the nested per-currency entries are what 04 T-CLS-05 rows 1.40 / 1.44 / 1.58 already specify for the frozen file — **Q2 for Codex:** widen the engine annotation or flatten; default: pass through, widen the annotation in the engine module's docstring only if Codex agrees). No column renaming, no re-rounding, no live label substitution; a row lacking a column or a repeated row key refuses by name.

## 11. Amendment A1 (same day, before review; corrects D4 / §3) — the freeze must not depend on the approver's report scope

`framework._resolve` filters `entity_codes` through `_in_scope_entities(session, uow.principal)`, i.e. the caller's `report.run` permission scope (`framework.py:773–780`). The PERIOD_LOCK decision runs under the approving Controller's principal (`commands.py:1514+`), who need not hold `report.run` for the lock's entity — so an adapter that called `_resolve` verbatim would let a freeze fail on the approver's REPORT permissions, which is not a property of the lock. **Decision (D4a, replaces the "through `_resolve`" wording of D4 / §3 / §2 step (3)):** the adapter derives the request parameters with the SAME normalisation as `_resolve` but WITHOUT the principal scope filter — the schema defaults, `PARAMETER_DEFAULTS`, booleans false, `known_at` as `utc_text`, the basis from `resolve_basis(given, known_at_given=True)` (= `historical`), `as_of` none, `book` = the scope's book — and `entity_ids = (scope.entity_id,)` by construction (the lock's entity IS the scope); `parameter_errors(schema, given)` still guards the closed schema (unknown keys, types) and any finding refuses by name. The normalisation lives in one helper (`snapshots.scope_parameters(definition, scope, entity_code, period_key)`), and a CPU parity witness pins that, for each of the ten reports, it equals `_resolve`'s result for a principal whose `report.run` scope holds the entity (same `parameters`, `known_at`, `historical`, `book_code`, `as_of_date`, `entity_ids`). The freeze's authorisation is the lock decision's (BR-CLS-02, BR-PLT-06, the gates) — never a second report-permission check.

### 12.1 Return (1) — default presentation rows are NOT canonical snapshot rows; the governed grain per kind

**Source of the operative contract.** The re-lock consumer `close/relock_diff.py::KEY_COLUMNS` (:97–:272) is the committed statement of every kind's key columns (ENGINE_SPEC_B §15.2.7 row keys as CSV headers; S15-R-20a `:2280`): `_keyed` (:298–:316) refuses a header lacking a key column (`RELOCK_DIFF_KEY_MISSING`) and a repeated key tuple (`RELOCK_DIFF_KEY_DUPLICATE`), keying each row on `row.get(column) or ""`; `KeySpec.measures / measure_patterns` name the money columns the diff classifies. The dataset a registry adapter freezes MUST satisfy that consumer for its kind — that, not the live report's default presentation, is the canonical shape.

**Why the generic default wrapper fails (Codex, verified in source).** `revenue_waterfall.build` (:468–:530) defaults `row_dimension` to `CONTRACT` (`_row_key` :373–:381 sums every obligation of a contract into one row), emits WIDE period columns `period:<bucket>` (`_columns` :410–:441) and no `period_key` column, omits `obligation_key` unless the dimension is `OBLIGATION`, includes `currency` only when the population is mixed (:422–:423, :525–:530) and appends `TOTAL:<ISO>` rows whose identity columns are NULL (:511–:523) — while `KEY_COLUMNS[WATERFALL]` requires `entity_code, contract_external_id, obligation_key, period_key` (long form). `rpo.build` (:832–:896) defaults to `CONTRACT` aggregation (`_dimension_key` :787–:799; `_grouped` :802–:811), emits `TOTAL:<ISO>` rows and puts `obligation_key` only on section-2 exempt rows; `OBLIGATION` is not an admitted `row_dimension` (`catalogue.py:549–:551`: CONTRACT, ENTITY, PRODUCT_FAMILY, CUSTOMER_SEGMENT) — while `KEY_COLUMNS[RPO]` requires `entity_code, contract_external_id, obligation_key` and names `section` a discriminator, not identity (:151–:158). One contract with two obligations is the counterexample for both: one default row, two governed keys.

**Decision A2-1 — two kinds are produced from the builders' REAL consumed populations at the governed grain; eight kinds wrap `build()` with the presentation totals removed; all twelve contracts are stated.** No proxy identity, no key broadening, no second calculation: the long-form rows reuse the same population objects and the same figure helpers the report uses.
