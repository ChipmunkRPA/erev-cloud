# Spec questions: phase 04 WEB (Frontend foundation, platform screens and e2e harness)

Archived from `PROGRESS.md` verbatim. SPEC-Q-196 to SPEC-Q-226 (WEB-1 to WEB-3 and WEB-3a to WEB-3d) moved during WEB-4 and SPEC-Q-227 to SPEC-Q-243 (WEB-4 to WEB-6) during WEB-7, to keep `PROGRESS.md` under 20 KB; the remaining WEB questions join them when GATE-WEB is ticked.

- SPEC-Q-196 (WEB-1; dev-guide DG-FE-04 `createClient<paths>({ baseUrl: "/api/v1" })` vs `docs/api/openapi.json`, whose paths already begin with `/api/v1`): a base of `/api/v1` would double the prefix in every typed call, so `api` uses the page origin as its base and typed calls name the full generated path (`api.GET("/api/v1/jobs/{job_id}")`). `useCommand` paths are full API paths as well.
- SPEC-Q-197 (WEB-1; DG-FE-05 "once per user intent" leaves the intent boundary open): an intent is a body. The key is reused while the same body is resubmitted and no 2xx has answered; a 2xx (including 202), a different body or `reset()` starts a new intent. The api stores only successful responses (`run_command`), so resending a key after a problem or a lost response cannot replay a stale failure.
- SPEC-Q-198 (WEB-1 scope list vs `import.meta.env`): `frontend/src/vite-env.d.ts` (`/// <reference types="vite/client" />`) and `resolveJsonModule` in `frontend/tsconfig.json` were added so `t.ts` can read the build mode and import `messages/en.json`; neither path is in the item's scope list.
- SPEC-Q-199 (WEB-2; DESIGN_SYSTEM DS-FMT-03 and DS-I18N-09 "minor units come from the API currency reference" vs no currency route before phase RFD): the format module holds a registry (`registerCurrencies([{code, minor_unit}])`) and an unregistered currency throws (XR-12 fail closed) rather than using Intl defaults. The first item that serves the currency reference registers from it. Tests register USD 2, JPY 0, BHD 3, CLF 4.
- SPEC-Q-200 (WEB-2; dev-guide DG-FE-20 "instants in the browser time zone with an explicit abbreviation" vs DS-FMT-17 and the WEB-2 acceptance `07 Sep 2026 18:05 UTC`): followed DS-FMT-17 and the acceptance. `formatTimestamp` renders UTC; the local-time tooltip belongs to the component that shows it. Also: the WEB-2 scope lists `frontend/src/styles/app.css`, but `num-pos` is already a tokens.css `@utility` that Tailwind emits when `<Money>` uses it, so app.css is unchanged. `tsconfig.json` gains `ES2023.Intl` for string input to `Intl.NumberFormat`.
- SPEC-Q-201 (WEB-3; DS-ICO-02 "re-exports only the icons listed in DS-ICO-07" and the registry test vs the DS-CMP-02 rail icons House, FileText, CalendarDots, LockKey, SealCheck, Scales, which DS-ICO-07 does not list): the registry holds exactly the 56 DS-ICO-07 names; WEB-8 (rail) adds the DS-CMP-02 icons and widens the test to DS-ICO-07 plus DS-CMP-02. Phosphor 2.1 deprecates the plain names, so the registry deep-imports `<Name>Icon` and re-exports it under the DS-ICO-07 name.
- SPEC-Q-202 (WEB-3; SCREENS §0.8 maps E-05 `VOIDED` only for `void_reason` STALE_SUBJECT and SUBJECT_VOIDED vs 04 T-PLT approval_request `void_reason` WITHDRAWN_BY_PREPARER): `chipFor` shows Void for every void reason except STALE_SUBJECT.
- SPEC-Q-203 (WEB-3; DS-CMP-20 "16 px spinner replaces the leading icon" vs tokens.css, which defines no spin keyframes, only `erev-progress`, and DS-MOT-02/03): the loading mark is the static Running icon CircleHalf, and `aria-busy` carries the state. DS-CMP-20's compact 10 px padding has no density utility, so buttons keep 12 px.
- SPEC-Q-204 (WEB-3 scope list vs paths added): `components/ui/cn.ts`; `components/form/Listbox.tsx` (the popup listbox shared by Select, Combobox, MultiSelect and PeriodInput); `lib/format/index.ts` gains formatDuration (DS-FMT-24), formatElapsed, parseDateInput, calendar arithmetic, weekdayNames and utcDateOf, because DG-FE-20 confines date handling to the format module (tests `lib/format/duration-dates.test.ts`); `app/providers.tsx` mounts IconContext (DS-ICO-04) and ToastProvider; `NOTICE` names Phosphor (DS-ICO-01). react-hook-form and zod (DG-FE-06) are not added yet: the field components are controlled with render props, so the first form screen adds them.
- SPEC-Q-205 (WEB-3 copy that no document fixes): announcements "Completed: <job label>." and "Cancelled: <job label>." (DS-A11Y-08 names no copy); "Enter an amount such as 1,234.56.", "Enter at most <n> decimal places.", "Enter a whole amount without decimals.", "Enter a date such as 07 Sep 2026."; "Dismiss", "Dismiss message", toast region "Messages". The date picker week starts on Monday (ISO 8601). A banner cannot detect "present on load", so the caller sets `announce="static"` or `"live"` (default live).
- SPEC-Q-206 (WEB-3a; D-80 MFA rule 3 "after the later of `user_mfa_factor.updated_at` and `app_user.locked_until`" vs the time bases): `security_event.occurred_at` and the factor's `updated_at` come from the database clock (`now()`, touch trigger), while `locked_until` holds the request clock (FrozenClock in tests), and a successful password sign-in clears it. The count therefore anchors the lock by the chain position of the user's latest `ACCOUNT_LOCKED`, written in the transaction that sets `locked_until`; nothing is counted while locked, so both anchors mark the same point. A spent recovery code touches the factor, so `updated_at` marks every successful verification.
- SPEC-Q-207 (WEB-3a copy and check order): the reset refusal reads "Only an active or suspended member's multi-factor authentication can be reset." (field `status`, rule SM-13). The MFA lock reuses the sign-in lockout copy, and the 429 the sign-in copy. `reset_mfa` checks step-up (403), the membership (404), an operator target (404), own membership (403), status (409), then the factor (409).
- SPEC-Q-208 (WEB-3a; D-80 "read `audit_chain_head` in the same transaction"): `verify_tenant_chain` reads the head before the events and walks up to the head's position. Under READ COMMITTED an append commits its event and the head together, so concurrent appends cannot give a false FAIL. A head the session cannot see (an owner connection without a policy) fails closed with "the audit chain head is missing". Range verifications (`to_seq` given) are not anchored. `record_tenant_verification` checks the earlier PASS only when the chain passed; "latest" orders by `finished_at`, `to_chain_seq`, `id` descending; the FAIL keeps the checked range.
- SPEC-Q-209 (WEB-3a; T-PLT-04 reset audit in other workspaces): the acting workspace's unit of work audits the command; the events of the user's other ACTIVE workspaces are written after commit in their own transactions, as `_audit_enrolment` does, with `actor_roles` empty, `support_grant_id` null (the actor holds nothing there) and `detail.acting_tenant_id`. A failure there is logged, not raised (DG-KRN-UOW-02).
- SPEC-Q-210 (WEB-3a scope "security notes under `docs/security/`"): no file existed, so `docs/security/security-notes.md` holds per-item notes until SOP-9 writes the threat model and ASVS checklist.
- SPEC-Q-211 (WEB-3b; D-80 MFA-reset row rule 5 "an INVITED membership" vs "until the membership is accepted"): the identity is withheld while `activated_at` is null and the status is INVITED or REMOVED, so an invitation removed before acceptance does not disclose it either. ACTIVE and SUSPENDED rows always show it. The users list sorts and searches on the shown name (`users.SHOWN_DISPLAY_NAME`), so `q` cannot probe a withheld name; that touches `api/v1/users.py`, which the scope list does not name.
- SPEC-Q-212 (WEB-3b; D-80 "refuse http or loopback issuers under production" vs SAR-15 "loopback and http only in dev, test and e2e"): `_issuer_valid` allows http on a loopback host only under dev, test and e2e, and refuses loopback hosts (127.0.0.0/8, `::1`, `localhost`) in any other environment. The refusal copy there is "Enter an https issuer URL on a public host without a query or fragment." (no document words it).
- SPEC-Q-213 (WEB-3b acceptance "injected settings whose env is production" vs `cli.CliServices`, which carried no settings): `CliServices` gains `env` (from `EREV_ENV` in `cli_services`), and `support.operators.operator_services` takes `env` (default TEST). `LOCAL_ENVIRONMENTS` is now public in `config.py` and shared by the guard and `auth/oidc.py` (the kernel may not import adapters).
- SPEC-Q-214 (WEB-3b; D-80 address rule lists `is_global`, `is_multicast`, `is_reserved`, `is_unspecified` vs the acceptance address `fec0::1`, which Python 3.12 classifies as global and not reserved): the guard also refuses `is_site_local`. NAT64 and IPv4-compatible extraction excludes `::` and `::1`. `check_host(host, port, env)` holds the address rule for SMTP, which has no URL; the SMTP client subclasses `smtplib.SMTP._get_socket` to connect to the checked address while STARTTLS verifies the host name. A refused OIDC URL raises `OidcDestinationRefused`, both `DestinationRefused` and `OidcHttpError`.
- SPEC-Q-215 (WEB-3b copy and evidence choices): the rename refusal reads "Only a person this invitation added to eRev can be renamed." (field `status`, rule SM-13). `PASSWORD_CHANGED` names the successor session, as `TENANT_SELECTED` and `MFA_ENROLLED` do after `reissue`. `test_change_password` presents a session with the workspace open (`workspace()`), because `GET /me` answers 401 for a session without one (`require_authenticated`), not because of the rotation.
- SPEC-Q-216 (WEB-3c; D-80 "claimed and committed, then posted" vs the acceptance's 121 s jump inside the first POST): the in-flight claim still lapses, so after the committed claim the recording transaction locks the row while the stamp holds, posts and records before committing; `SKIP LOCKED` claims skip it (lock at most 10 s). "`DELIVERED`" names no E-97 literal: asserted `SUCCEEDED`.
- SPEC-Q-217 (WEB-3c; ADP-32 "older than 15 minutes"): strict `updated_at < now − 15 min`, so the exact 15-minute jump does not re-claim; a stopped relay's message is re-claimed after 15 min 1 s. - SPEC-Q-218 (WEB-3c; D-80 rule 5 "counts only QUEUED rows whose task is todo or doing"): RUNNING jobs still count as pending (otherwise each minute sweep would defer a second job beside a running one); a QUEUED row without `procrastinate_job_id` no longer counts.
- SPEC-Q-219 (WEB-3c; 05 §5.6 vs registered policies): `OUTBOX_RELAY` and `EMAIL_DELIVERY` had one attempt, and a stranded task counts as one, so the relay could not be re-dispatched. Now relay 8 attempts (ADP-12: 30 s doubling, cap 900 s), email 5 (30 to 240 s).
- SPEC-Q-220 (WEB-3c stranded recovery): a task carries one `attempt` argument, so the task id identifies the attempt (the row stores none). In-place stall retries keep the argument; the sweeper counts argument + Procrastinate `attempts`, so such a job may run once more than its profile. Past the last attempt: QUEUED → RUNNING → FAILED in one transaction (no QUEUED → FAILED pair), `job-stalled`, detail "the worker task stopped before the job started" (unworded). Only QUEUED jobs are recovered. `get_stalled_jobs` runs via `asyncio.run` and `registry._SessionConnector`. `sweep` counts recoveries as requeued.
