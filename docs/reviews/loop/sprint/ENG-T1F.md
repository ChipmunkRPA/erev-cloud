## T1F-89-1 — the exact revenue-activity operand for `revenue_amount` (design note; Codex production-20260921-1155 §1, relayed by the supervisor; 2026-09-21)

**Facts (source at 63be0717; `schedule.py` byte-identical to main):** `revenue_amount` = Σ over the version's NEW events (`ev.is_new`, effective ≤ v, the obligation's contract or one of its boundary events) of `evaluator.posted_value(d, Position(order_key, inclusive=True)) − posted_value(d, Position(order_key, inclusive=False))` at the ENG-06 positions (`schedule._revenue_effect_items`; `ObligationMeasures.revenue_amount` = their sum; CV-64). **The exact operand exists in existing state — nothing new is computed and nothing is stored:** `components.Evaluation.exact` is Σ E_c of the segment targets in currency units — the exact cumulative target BEFORE half-up posting (the `revenue_cum` node already carries it: `_emit_components` emits `rec.revenue_cum.v1` with `exact=ev.exact`, so its `rounding_residue` = exact − posted per period and at the version date). `Evaluator.posted(d, position)` returns that `Evaluation` at the same ENG-06 positions the posted path uses: manual adjustments, holds and S02-R-04 netting change `value` only; `exact` stays the segment exact. **Bound and consistency (CV-35 untouched):** per position C = `money.cumulative_posted(X, A, f, μ)` ∈ [0, A] (A = round(X)) while E = X × f ∈ [0, X] for f ∈ [0, 1]; round is monotonic so round(X f) ≤ round(X) = A and the clamp never binds for X f ≥ 0 — |E − C| ≤ ½ minor unit at every unadjusted position (f = 1: C = A, E = X, |X − A| ≤ ½ unit). An activity's residue is the sum over its new events of (ΔE − ΔC), each the difference of two per-position residues. The posted path (values, journals, `period_amounts`) is not touched.

**Where the exact is NOT derivable — stated, never manufactured:** when either position's evaluation is `adjusted` (a manual adjustment, a hold's frozen level, or the S02-R-04 netting changed the posted target), the target is DEFINED in posted units by its rule and has no exact counterpart in state; nothing could be stored to create one short of redefining those rules. A guarded position has exact 0 = value 0 (S02-R-03). PERIOD_VC realised amounts are money inputs (exact = posted) and enter E_c as such.

**Emitter change (proposed; `schedule.py` only):** `_revenue_effect_items` returns (event, posted delta, exact delta | None); `_Parts.revenue_effects` carries it; `activity("revenue_amount", …)` passes `exact = Σ exact deltas` (currency units) when every delta is derivable, and each `contract_event` SourceRef detail gains `exact = format_exact(exact delta)` beside `value`, so the residue is re-derivable from the node's own inputs (CV-53: detail members are derived values).
