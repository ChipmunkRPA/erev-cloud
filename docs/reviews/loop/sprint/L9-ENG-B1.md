## Deviations and notes

- `billing_mode_at(policies, entity, on)` takes the entity view (`EntityView`), not an entity code: the period lookup needs the calendar, and the CV-12 "no calendar" check stays with the callers (`classification._mode`; `returns._billing`). D-91 writes `(policies, entity, on)`; the package wrote `entity_code`.
- `_billed_lines` returns `tuple[BilledLine, ...]` as the package states; the counts of skipped status updates and memo-only lines and the mode at d travel on a private `_Billing` container from `_billing`, which `return_state` reads into the new `ReturnState` fields.
- `BilledLine` is (`ref_id`, `value`, `contribution`, `keys`, `weights`, `detail`) with an `apportioned` property; the package named no members.
- The E_b node's inputs are the expected-units and units-billed nodes, so the E_b node exists only where `returns.emit` traced an expected-units node (a FIXED part with a REDUCE returns target carrying E). A `ReturnState` without one (guard, no FIXED part in force, or a RESTORE reversal chain) keeps the stored-trace `rl.return.v1` form so no RETURN component loses its node; no corpus key or lane test reaches that branch.
- The `mode` param of `return_units_billed` is the billing mode of the contracting entity at the measurement date d; each line's own dating uses the mode at the line's date (S09-R-23a). The two differ only when POL-004 varies by period between a line and d (return item, below).
- `status_updates_skipped` counts the identity's status updates admitted at d (a repeat dated after d is not counted); `memo_only_lines` counts the kept lines admitted at d with no unconditional source.
- Stage 04 gap params: `payment_points` is the `|`-joined `<ISO date>:<exact amount>` list of the derived points after netting; `status_updates_ignored` is the count as a string, with `status_updates_ignored_keys` (the `|`-joined event keys) added only when the count is positive. The package's "(count; event keys joined by `|`)" admitted both readings; both are additive.
- The receipts branch of `_judged_points` now records the first receipt event per date as the point's source (the CSP SourceRef names it); the package spoke of the billing branch's line events. Values unchanged; trace ref ids differ for SFC-FS-11-CASEB and the other receipts-branch keys.
- `_judged_points`'s return type changed from a 2-tuple to `JudgedPoints`; `_assess_judged` takes it. Both are private to stage 04.
- The financing tests re-sequence injected events in ENG-06 order (`_resequenced`) because an event recorded after the 31 Dec 2027 delivery and dated in 2026 is an S08-R-10 `OUT_OF_ORDER` late event; the scratch prototype's test did not assert `diagnostics == []`.
- The kernel test's stage 04 consumers receive a `SimpleNamespace(identified.canonical.events)` stand-in for `PobState`; `_judged_points`, `specialist.invoices` read nothing else.
- The obligation-key mismatch finding is emitted in addition to the amount finding when both apply (two findings on one event); the amount finding's detail is unchanged (no `member`).
- `test_chk_alg06::test_chk_029_refund_liability_and_return_asset` is an existing engine unit test that pinned the `rl.return.v1` node with an `e_b` param; D-91 (7) switches the RETURN component to `rl.return.v2`, so the assertion follows (not an answer-key value).
