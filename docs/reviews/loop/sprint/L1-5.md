- `backend/erev_api/domain/demo/seed.py`: `seed_demo(tenant_codes, clock, *, keyring, files, secrets, credentials_path, request_id, os_user, personas)`. Per tenant, all through commands (WLD-R-02, BS1-D-20):
  1. `provision_tenant` as the CLI operator, admin `tomas@demo.erev`.
  2. `tomas` accepts through `memberships.accept_invitation` with `EREV_DEMO_PASSWORD`. The token is read from the invitation email's `link_path` in the outbox.
  3. Every `requires_mfa` persona enrols TOTP with `EREV_DEMO_TOTP_SECRET` (`mfa.enroll` + `mfa.confirm`) the first time; recovery codes are kept for the credentials file. A persona enrolled by an earlier run verifies with `mfa.verify` instead. The verified session then opens each further workspace through `sessions.select_tenant`, keeping its verification.
  4. `tomas` runs `users.invite_user` for each persona with its roles for all entities (route guard `user.manage` checked), and `AUTO-BOOTSTRAP` approves each assignment. Each persona then accepts.
  5. `tomas` runs `roles.create_role` for `deal_desk_analyst` (guard `role.manage`), and `grace` approves the `ROLE_CHANGE` through `approvals.decide` with an MFA-verified principal. Only then is `jordan` invited with `viewer` and `deal_desk_analyst`.
  6. The SYSTEM principal audits `demo_seed.complete` with `generator_seed` 20260912, `generator_version` 1, and the WLD ids of the tenant and its personas.

  Before any write, the cast, password and TOTP seed are validated, and the tenant directory is read once. A tenant with `is_demo` false, one left unfinished, or one built by another generator version is refused. A tenant built by this version is skipped with log `seed.tenant_skipped` (`tenant_code`). Recovery codes are merged into `<run_dir>/demo-credentials.txt`, written 0600 beside the target and moved over it. No password is written (DG-RUN-32).
- `backend/erev_api/cli.py`: `erev seed demo --tenants <all or codes>`. It prints `seeded <code>` / `skipped <code>` and the credentials path. A refusal goes to stderr with exit 1, and a `Problem` to stderr as JSON with exit 1. The command refuses outside `dev`, `test` and `e2e`. `CliServices` gains an optional `run_dir` (defaults to the settings).
- `Makefile` target `seed` (DG-MK-seed): `REQUIRE_SETUP`; fail `FAIL seed: EREV_DEMO_PASSWORD is not set. Copy it from .env.example.` when the variable is absent from both the environment and the `.env` named by `EREV_DOTENV` (the value is never expanded or printed); `RESET=1` runs `make db-reset`; then `EREV_ENV=dev erev seed demo --tenants "$(TENANTS)"` (`TENANTS ?= all`).

### Deviations and defects fixed

- **Product defect fixed** (`backend/erev_api/approvals/engine.py`). `_membership_of` looked up the preparer's membership by `user_id` alone. RLS-TM's permissive self policy shows a signed-in user their memberships in every tenant, so an auto-approved request by a Tenant Admin who belongs to two workspaces raised `MultipleResultsFound`. The seed hit it in the second tenant. The lookup now names the request's `tenant_id`; the regression is covered by `test_bs1_d_20_commands_as_personas` and `test_wld_u_personas_and_roles`.
- **Additive auth change** (`backend/erev_api/auth/mfa.py`). `enroll(..., secret_base32=None)` lets the seed enrol the documented demo seed (WLD-U-R2). Every other caller keeps a random seed.
- **Pre-existing environment-dependent test fixed** (`backend/tests/domain/platform/test_outbox.py::test_ntr_05_fake_email_file`). It hard-coded origin `127.0.0.1:5270`, while its `runtime` fixture uses `EREV_PUBLIC_ORIGIN`, which the lane `.env` sets to 5315 (D-81). It failed alone on HEAD before any lane change. The regex now uses `re.escape(runtime.public_origin)`. No other L1 lane touches the file.
- DG-RUN-32 (D-75) is followed where it supersedes WLD-U-R1's generation fallback: the seed never generates a password and fails when `EREV_DEMO_PASSWORD` is missing or empty.
- Not in WEB-10 acceptance and not built: the WLD-U-12 `svc-*` API clients and their WLD-U-R3 secrets; entities, periods and contracts (later items extend `seed.py`).

### Spec questions

- **L1-5-Q-1** "a second run writes no row": finding a tenant by code needs `app.platform_scope = 'tenant_directory'`, which DG-KRN-DB-03 records as one `PLATFORM_SCOPE_USED` security event. The seed reads the directory once per run. The test asserts that this event is the only new row; every identity, security and tenant row count is otherwise unchanged.
- **L1-5-Q-2** `tomas`'s display name stays his email. Provisioning creates the bootstrap admin with the email as name (SPEC-Q-118); no self-rename command exists; `PATCH /users/{id}` cannot rename after acceptance (D-80 rule 6); and WLD-R-02 forbids a direct `app_user` write. The other personas get their PRD names through `invite_user`.
- **L1-5-Q-3** DG-MK-seed defines only the skip for "a tenant already seeded by the same generator version". The seed refuses, before any write, a demo tenant without `demo_seed.complete` ("an earlier run did not finish; run make seed RESET=1") and one built by another version. The version marker is the SYSTEM audit event `demo_seed.complete`, not `tenant.industry_cluster`, which holds the PRD cluster codes.
- **L1-5-Q-4** Copy for an unusable `EREV_DEMO_TOTP_SECRET` (not base32, or under 80 bits): "EREV_DEMO_TOTP_SECRET must be a base32 secret of at least 80 bits. make setup adds one when the line is absent." No document words it.
- **L1-5-Q-5** `erev seed demo` refuses `EREV_ENV=production` ("erev seed demo runs only with EREV_ENV dev, test or e2e"). WLD-R-05 and DG-MK-seed imply local use only.
- **L1-5-Q-6** "`make seed` exits 1": the recipe exits 1 and prints the message, but GNU make reports a failed recipe with exit status 2. The test asserts `[seed] Error 1` and make's exit 2.
- **L1-5-Q-7** BS1-D-20 creates `deal_desk_analyst` "in WLD-T-01"; PRD §2.3 gives Jordan "same" roles in WLD-T-02 to 07. The seed creates it (as `tomas`, approved by `grace`) in every tenant where Jordan is a member. The tests assert Avenmoor only.
- **L1-5-Q-8** A persona enrolled by an earlier run verifies with the code of step t+1 (inside `totp.WINDOW`). A further verification within the same 30-second step (for example two partial runs in quick succession) would be refused as a replay; the seed then fails loudly and a later run succeeds.
- **L1-5-Q-9** `backend/erev_api/jobs/registry.py:858` (JOB_FAILED notification) selects `tenant_membership.c.id` by `user_id` without `tenant_id`, the same RLS-TM pattern as the fixed `_membership_of`. For an initiator with memberships in several tenants it would notify membership ids of other tenants. It is not changed here: no test in this batch covers it, and the file is outside the lane scope.
