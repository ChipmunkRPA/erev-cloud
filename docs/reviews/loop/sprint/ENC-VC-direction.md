## Design implemented (final)

1. **Carry the direction.** `EstimateVersionInput.direction: str | None = None` (the T-CON-12 column; `None` when the producer carried none) and `resolved_direction()`: an explicit value is honoured within the T-CON-12 CHECKs (unknown literal, an IPC element not DECREASE, a DECREASE on a kind without a direction → `ValueError`, CV-45); `None` applies the B3-DG-17 default exactly. Public constants `INCREASE`, `DECREASE`, `DIRECTIONS`, `VC_DECREASE_TYPES` in `erev_engine.bundle`. Stage 04 `vc.direction()` delegates to it (measurement, trace params `direction`/`sign`, formulas unchanged). Stage 01 `pins.build` asserts every version of one element resolves to one direction (B3-D16; `ValueError`, CV-45). The production bundle (`estimate_version_input`) transmits the stored `direction` with magnitude amounts (the L5 `_vc_sign` workaround removed); the API dry-run takes the same path; the answer-key runner transmits the loaded key's `direction` (explicit or loader-derived). The parity VC element (runner and `golden_streams`) keeps its pre-lane representation (signed golden price, no direction) so no all-active key changes; the CTR-12 form is Q-3.
2. **Defaults preserved.** Absent direction ⇒ B3-DG-17 (VOLUME_TIER absent ⇒ DECREASE): tested for 14 types (s04) and on the VC-FS-02 world (s10: absent and explicit DECREASE keep the historical ACCOUNT_MAPPING_MISSING).
3. **Stage 10 per the model-scope ruling** (`refund_liability.py`): `explicit_target(version)` reads the T-CON-13 member (absent and explicit `null` both "absent = 0"; `"0.00"` is a target). `refund_candidate(version)`: with an explicit target, the type must be one of the five refund-settled types (REBATE, PRICE_PROTECTION, REFUND, SLA_CREDIT, DISCOUNT) — either direction, non-negative including zero; without a target, only a DECREASE element of a refund-settled or derived type (the D-87 form measures a reduction, K_t). An INCREASE element without a target never reaches the producer (no component, no node, no REFUND_LIABILITY account). `refuse_unsupported_target(version, key)`: an explicit target (including zero) on any other type fails closed before any component — `ENGINE_INVARIANT_VIOLATED`, detail `rule = CV-45`, `reason = REFUND_TARGET_TYPE_UNSUPPORTED`, `vc_element_type`, `direction`, `estimate_version_key`, `supported_types = DISCOUNT|PRICE_PROTECTION|REBATE|REFUND|SLA_CREDIT`, `route` (model a separate refund-settled element carrying the target, or omit the target and let a DECREASE derived-type element derive the billed excess); the message names the same. The per-period measurement: explicit target → its value (JET-04b target); else DECREASE and `derives(book, type)` → the D-87 excess; else 0. `derives()` keeps the type/book gate. No 04 §15.4 code exists for the refusal; the CV-45 code is used and a dedicated code is Q-2.
4. **CV-25 hash view (D-93 (5)).** `EstimateVersionInput.hash_view()` writes `direction` into the input hash only when it differs from the B3-DG-17 default the engine would derive without it; `InputBundle.sha256()` hashes estimate versions through it. This is a canonicalisation of pre-0.3.0 bundles: an absent member and an explicit default-equal member are omitted and hash identically to the pre-member form; a non-default explicit direction is a different input and hashes differently. Limits: the view depends on the B3-DG-17 default list (a change to that list changes hashes); an explicit default-equal direction is indistinguishable in the hash from an absent one; only the CV-25 view normalises, the dataclass encoding keeps the field (DG-KRN-CAN-13); and the view still carries `engine_version`, so every actual 0.3.0 input hash differs from its 0.2.0 one. A CV-25 sentence is needed in ENGINE_SPEC (Q-1).
5. **VC-FS-02 input.** `direction: INCREASE` with a YAML comment block and one summary sentence recording the ruling (the key schema has no notes member: `models.AnswerKey`, `extra="forbid"`). Expected values untouched.
6. **Version.** `ENGINE_VERSION` 0.2.0 → 0.3.0: a changed-result minor bump under the D-91 A4 reading of DG-ENG-10 for the 0.x line (D-93 (5); see the hash and version section).
