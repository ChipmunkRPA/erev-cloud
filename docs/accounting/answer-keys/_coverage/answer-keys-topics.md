## 1. Result

- All 101 keys generate and verify with 0 errors. The verifier reloads each file with a DG-AK-31-style loader (null and bool resolvers only). It strips the checkpoint values, recomputes every asserted leaf from the parsed inputs and requires string equality.
- The verifier also lints what it can check statically:
  - schema literal, id pattern, and agreement between family, path and id;
  - families and tags;
  - CHK, REQ and POL ids (every CHK id must be contained in the key id);
  - policy keys and literals;
  - enums for templates, SSP, estimates, modifications and judgements;
  - account roles and `clearing_purpose`;
  - timeline `seq` continuity;
  - runner restrictions (no commands, journals, reports or period states);
  - money places;
  - the DG-AK-54 implicit checks where the fields are asserted: DB-17, P1 and balanced exact subledger blocks.
- `.scratch/design-answer-keys-topics/verify-report.json` records the SHA-256 of every key.
- Golden cross-check (`check_golden.py`): the parity oracle replays the key inputs and compares them with the legacy golden `Contract_Live` rows (cumulative revenue, remaining allocation, remaining SSP, remaining quantity). Result: 508 comparisons, 0 mismatches at 1e-4 (D-17). Golden figures are never oracle inputs.

## 8. Input conventions used by the keys

| # | Convention |
|---|---|
| T-01 | SSP `point_value` is per unit; weight = point × line quantity. Parity rows carry the legacy range inputs `unit_list_price`, `midpoint_discount_ratio` and `range_ratio` |
| T-02 | A posted allocation is one largest-remainder apportionment of the transaction price over the exact quotas X_p, including targeted VC (OQ-AKT-04) |
| T-03 | VC amounts are non-negative magnitudes; `vc_element_type` gives the direction. Reducing types: IMPLICIT_PRICE_CONCESSION, REBATE, VOLUME_TIER, PRICE_PROTECTION, SLA_CREDIT, DISCOUNT, RETURN, REFUND, PENALTY. Of these, REBATE, VOLUME_TIER, PRICE_PROTECTION and REFUND target a refund liability (JET-04b) (OQ-AKT-10) |
| T-04 | Expected-value versions carry `scenarios`. The oracle checks that probabilities sum to 1 and that `unconstrained_amount` equals the expected value (or the modal scenario under the most likely amount method) |
| T-05 | RETURN_RATE and ROYALTY_ACCRUAL versions carry `parameters` per 04 T-CON-13 rev 1.1 (industries OQ-AKI-01) |
| T-06 | Checkpoints that assert labelled balances use a period-end `as_of` |
| T-07 | ERP billing counts invoices on `issue_date`. ENGINE billing: `amount` excludes `tax_amount`, and a cancellable invoice enters the position only on the receipt that applies it (POL-123 `UNCONDITIONAL_INVOICES_ONLY`) |
| T-08 | Option SSP under `DISCOUNT_X_LIKELIHOOD` = `expected_purchase_amount` × `incremental_discount_ratio` × the EXERCISE_LIKELIHOOD `rate` effective at inception (D-21a). Points use an `OT_A` `REDEMPTION_PATTERN` template and a BREAKAGE version |
| T-09 | Modification `lines[].consideration_delta` is ΔC_m, and `price_change_amount` (T-CON-06) is the SATISFIED_PERFORMANCE amount. Pool = Σ over D and N of (A_p − R_p) + Σ ΔC_m − ΔC_sat + ΔVC effective at d (ALG-04 §2.5.5 `REMAINING_TP`) (OQ-AKT-05) |
| T-10 | Royalty statements (`USAGE_REPORTED` with `is_royalty_statement: true`) on a licence POB add revenue once the POB is at least partly satisfied, and never enter allocation (OQ-AKT-09) |
| T-11 | Financing: contract override `sfc.discount_rate_basis` = `{basis, annual_rate}`; monthly rate = annual_rate ÷ 12; instalment k falls due at the k-th month end after transfer |
| T-12 | Parity keys: preset `LEGACY_PARITY` (POLICIES §6.3); a named SSP version; legacy negative VC rows as contract-level DISCOUNT elements (POL-213); negative delivery and billing rows as `RETURN_RECORDED` and `CREDIT_MEMO_RECORDED` (D-22); posting rule EXACT-CUM |
| T-13 | Agent POBs carry the retained consideration on the line and the gross amount on the invoice. The supplier portion posts to `BILLING_CLEARING` `AP_SUPPLIER` (industries OQ-AKI-05). Consideration payable uses the EXPECTED_PURCHASES encoding of industries OQ-AKI-04 |
| T-14 | Combined contracts are measured as one group. Per-member checkpoint blocks assert version and obligation values only; group balances appear only through entity-level subledger lines (OQ-AKT-06) |
| T-15 | Portfolio estimates are carried as one version per member contract (`RET-CHK-116`: 50 contracts) (OQ-AKT-07) |
| T-16 | Timeline order is (effective date, seq). Events on the same date apply in `seq` order, including status changes (OQ-AKT-20) |
